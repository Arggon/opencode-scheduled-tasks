# Deploy: how this project reaches production

Default deployment guidance per project shape, from ADR 0005
(cheap-path-to-prod) — this file is generated by `arggon init` from that
decision.
Every default is **config-in-repo**: an agent can execute it end-to-end from
files in this repo, and the exit path is always "redeploy elsewhere" — no
console-only setup, no proprietary state lock-in (databases/storage must stay
exportable).

## Free-tier gotchas (never hidden)

- Cloudflare Workers free: 10 ms CPU per invocation, 3 cron triggers,
  KV 1k writes/day — hard caps, but no spin-down.
- Render free: spins down after ~15 min inactivity (~1 min cold start) —
  unacceptable for anything user-facing; that is why it is not the default.
- GitHub Pages: soft 100 GB/month bandwidth limit, 10 builds/hour.

## Agent checklist

1. Classify the project shape (static / SPA+small API / long-running / jobs).
2. Add the default's config to the repo (e.g. `wrangler.jsonc`, a Pages
   GitHub Actions workflow, `fly.toml`, or systemd units under `deploy/`).
3. Deploy from CI or the CLI — no console-only steps.
4. Before relying on any price above, re-check it (last verified 2026-09-14).
